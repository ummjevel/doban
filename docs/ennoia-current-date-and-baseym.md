# 엔노이아 current_date / baseYm 처리안

## 문제

챗봇이 현재 날짜를 알고 있는 것처럼 답변할 수는 있지만, API 파라미터 생성 단계에서 최신 기준연월(`baseYm`)을 제대로 반영하지 못하는 경우가 있다.

예:

- 현재 날짜를 물으면 올바르게 답한다.
- 그러나 실제 API 조회에서는 예전 테스트값인 `202410` 또는 임의의 과거월을 사용한다.

## 원인

현재 날짜 정보가 모델의 답변 컨텍스트에는 있어도, API 커넥터 호출 파라미터를 만드는 단계에 명시적으로 전달되지 않으면 모델이 기존 테스트값이나 이전 성공값을 사용할 수 있다.

또한 공공데이터 API는 현재월 데이터가 바로 제공되지 않으므로, 현재 날짜를 그대로 `baseYm`으로 쓰면 안 된다.

## 권장 처리

엔노이아 플로우에서 날짜 관련 변수를 명시적으로 만든다.

```text
current_date = 오늘 날짜, 예: 2026-06-05
current_month = 202606
candidate_baseYm = 202604, 202603, 202602, 202601, 202512, 202511
```

원칙:

- 현재월은 제외한다.
- 직전월도 집계가 늦을 수 있으므로, 기본 후보는 현재월 기준 2개월 전부터 시작한다.
- API별로 최신 데이터 제공월이 다르면 성공한 최신월을 저장한다.

예:

```text
현재 날짜: 2026-06-05
현재월: 202606
집계 안정성을 고려한 후보월:
202604 -> 202603 -> 202602 -> 202601 -> 202512 -> 202511
```

## API별 최신월 캐시

질문마다 같은 최신월 탐색을 반복하지 않도록, API별 최신 성공월을 저장한다.

```text
latest_baseYm_by_api = {
  "areaTarSvcDemList": "202504",
  "areaTarExpDsList": "202504",
  "areaTarSjrnDsList": "202504",
  "areaCulResDemList": "202504",
  "locgoHubTar": "202504",
  "tarRlteTar": "202504"
}
```

이 값이 있으면 우선 사용하고, 실패할 때만 후보월을 순차 조회한다.

## 호출 예산

API 호출이 과도하게 늘어나는 것을 막기 위해 아래 기준을 둔다.

```text
장소 확인: searchKeyword2 1회
지역코드 매핑: CSV/RAG 사용
최신월 탐색: API별 최대 6개 후보월
추이 분석: 핵심 API 1~2개만 최근 6개월
실패 API: 같은 조건으로 반복 재시도하지 않음
```

## 답변 표현

최종 답변에는 내부 탐색 과정을 쓰지 않는다.

쓰지 않을 표현:

```text
데이터를 조회합니다.
최근 6개월 데이터를 추가 조회합니다.
다시 시도합니다.
필요한 데이터가 확보되었습니다.
```

대신 답변에는 실제 사용한 기준만 쓴다.

```text
분석 기준: 부산광역시 해운대구, 2024년 11월~2025년 4월
주의: 일부 API는 해당 기간에 결과가 없어 확인된 지표 중심으로 해석했습니다.
```

## 추이 해석 주의

조회한 기간 안에서만 말한다.

예:

```text
2024년 11월~2025년 4월 구간에서는 12월 이후 완만한 하락 흐름이 보입니다.
```

조회하지 않은 기간을 단정하지 않는다.

피해야 할 표현:

```text
봄철 비수기 패턴입니다.
여름 성수기에는 회복될 것입니다.
```

권장 표현:

```text
여름 성수기 데이터가 포함되지 않아 연간 계절성 판단은 제한적입니다.
7~8월 데이터를 추가 확인하면 성수기 회복 여부를 더 정확히 볼 수 있습니다.
```
